Collect tester feedback in a Google Sheet

Bhaasa’s Give feedback screen offers selectable results for each feature, ease of use, problems, and whether the tester would use it again. Comments are optional. It works in the web, Android, iOS, and desktop builds. Google Apps Script receives submissions and writes them into your private Google Sheet; a separate hosting service or database is unnecessary.

This collector is optional and is not deployed automatically. Until you deploy it and configure the URL, reports are saved only on the tester’s device and can be exported/shared. A live Google deployment and real-phone delivery still need an end-to-end check under your account.

1. Create the Sheet and script

  1. In your Google Drive, create a Google Sheet named, for example, Bhaasa tester feedback. Keep its sharing private.
  2. From the Sheet, open Extensions → Apps Script. Name the script project Bhaasa feedback collector.
  3. Replace Code.gs with the complete Code.gs template in the repository. The source checkout also includes it in feedback-apps-script/Code.gs.
  4. In the Apps Script editor, open Project Settings → Script Properties → Add script property. Set property BHAASA_FEEDBACK_SHEET_ID to the Sheet ID: the text between /d/ and /edit in its URL. Save. Do not put the Sheet ID or credentials in the app.
  5. In Project Settings, enable Show “appsscript.json” manifest file in editor. Replace that file with the repository’s feedback-apps-script/appsscript.json. It uses V8 and only the Sheets OAuth scope. The owner authorizes this script; testers do not authorize it.

2. Deploy as a web app

  1. Choose Deploy → New deployment → Select type → Web app.
  2. Set Execute as: Me (the Sheet owner), and Who has access: Anyone. Authorize the Sheets access requested by your own script. Review the copied source before authorizing; Google may show an unverified-app notice for your personal project.
  3. Deploy and copy the Web app URL, which looks like https://script.google.com/macros/s/DEPLOYMENT_ID/exec. Use /exec, not the editor link, Sheet link, or development /dev URL.
  4. Open that URL in a private/incognito browser window without signing in. It should show “Bhaasa feedback collector”, not a Google login or permission page. This only checks deployment access; it does not test writing a row.

No OAuth client ID, JavaScript origin, localhost redirect URI, Google API key, or OCR/TTS gateway is needed for this feedback collector. The owner’s Apps Script authorization stays on Google’s servers. A Workspace administrator may disable anonymous deployments. If “Anyone” is unavailable, use local exports or a different permitted collector; a sign-in-only deployment will not work with this embedded anonymous submission flow.

3. Connect Bhaasa

To try it on one device, open Give feedback → Feedback collection settings, paste the /exec URL, and select Save collector setting. Submit a test response. Verify both Collector confirmed receipt in Bhaasa and the new row in the Sheet’s Bhaasa feedback tab.

For testers to receive the setting automatically, edit feedback-config.js before building/publishing:

export const APP_VERSION='0.7.1';
export const FEEDBACK_COLLECTOR_URL='https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec';

The deployment URL is public. It is safe to include in a build; it is not a secret or an API key. Distribute a new static/mobile/desktop build after changing it. A saved device override takes precedence; choose Use release setting to remove that override. To disable central sending on a device, save an empty URL.

When updating the script later, use Deploy → Manage deployments → Edit → New version → Deploy to keep the same URL. Saving the source alone does not update an existing versioned deployment.

Choices and optional notesDrafts autosave per language. A completed report is saved locally first. Only Save & send or Send / retry transmits it.

Local historyUp to 100 reports on that device/browser origin. Export all as JSON or share individual text reports before clearing storage. The form history includes both languages.

The Sheet remains private unless its owner shares it. This script exposes no endpoint for reading responses. Its submission endpoint is public, so anyone with the URL can submit: it is suited to a small trusted test group, subject to Apps Script/Sheets quotas and possible spam. Report IDs prevent accidental duplicate retries; they do not identify or count unique testers. This form does not replace Google Play’s opt-in, testing, feedback, or production-access process.

Only the tester’s explicit submission sends feedback to Google. Google processes the request under the owner’s account. Describe collection, purpose, access, retention/deletion, and a contact route in your app’s privacy notice, and reflect it in store privacy/Data safety declarations before distributing a collector-enabled release.

5. Delivery, retry, and deletion

Bhaasa posts a form to Google in a hidden receipt frame. The script validates the fields, locks the Sheet, appends the row, flushes the write, and sends a nonce-bound receipt back to the app. Bhaasa checks the receipt’s Google origin, frame, report ID, and request nonce. A plain page load or opaque network response is not treated as delivery confirmation.

Offline use, closing/backgrounding the app, timeout, a blocked frame, or a Google error leaves a local report with no confirmed receipt. Choose Send / retry on that same report after reconnecting. The collector checks its ID and returns the original receipt instead of adding another row. There are no automatic or background retries. If you change collectors, a retry sends the report to the newly configured Sheet.

Remove local copy removes only that device’s copy, not a row already in Google Sheets. The Sheet owner manages access, exports, retention, and deletion there. Backups and Google revision history can outlive a deleted row. Do not delete/change the report-ID column if you want duplicate detection to continue working.

6. Troubleshooting

  • No collector configured: paste the deployed /exec URL, or export/share without a collector.
  • No receipt after about 45 seconds: check internet access, anonymous “Anyone” deployment access, browser content blockers, and the Apps Script Executions log. Check the Sheet for the row before retrying the same report. No third-party Google sign-in cookie is required.
  • Collector not configured: set BHAASA_FEEDBACK_SHEET_ID in Script Properties, not User Properties or Bhaasa.
  • Sheets did not confirm saving: verify the owner has edit permission, authorized the script, has quota available, and used the supplied manifest. Keep raw server error details private.
  • Invalid report: deploy the matching current script version and app. Reports need at least one feature tried and an ease-of-use selection.
  • Android or iOS: use the latest native build and test on an actual device. Android allows only Google’s feedback receipt subframes to stay embedded; remote top-level links still open externally. No broad Capacitor allowNavigation setting is needed.
  • Local storage unavailable/full: the app cannot safely promise a saved report. Export existing reports and free storage. Existing unreadable report data is preserved rather than silently replaced.
