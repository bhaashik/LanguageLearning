Bhaasa on Android and iOS

The Capacitor mobile projects package Bhaasa’s lessons, fonts, phonetic guides, curved tracing, exercises, and scores on the device. No website hosting is needed for those features. Saved audio also plays offline. New cloud OCR and speech requests need a separate gateway; API keys stay on that server.

1. Prepare the mobile projects

Use Node.js 24 and a checkout of bhaashik/LanguageLearning. Run these commands in the repository folder:

git pull
npm run mobile:install
npm run mobile:sync

Mobile dependencies are isolated in mobile/. The regular web app still builds with npm run build without installing them. Sync rebuilds the mobile web assets and updates both native projects. Repeat it after changing lessons or app code.

The application ID is io.github.bhaashik.bhaasa. Keep that ID and the same release signing identity when distributing updates that should preserve installed data.

2. Android

Install Android Studio, JDK 21, Android SDK Platform 36, and Build Tools 35.0.0. The app targets Android 16 and supports Android 7.0 or later with an up-to-date Android System WebView/Chrome (109 or later).

npm run mobile:android

This syncs the app and opens mobile/android in Android Studio. Let Gradle finish, select an emulator or a USB-debugging phone, then click Run. To build an installable test APK from a terminal with ANDROID_HOME pointing to your SDK:

cd mobile/android
./gradlew assembleDebug

On Windows use gradlew.bat assembleDebug. The result is mobile/android/app/build/outputs/apk/debug/app-debug.apk. Copy it to your Android phone and open it, allowing installation from that source when Android asks. You can also use adb install -r app/build/outputs/apk/debug/app-debug.apk from mobile/android.

For a Play Store release, use Android Studio’s signed Android App Bundle option and your own release keystore. Keep the keystore private and backed up. Debug APKs are for testing; their signing keys can differ across computers and CI runs.

3. iPhone and iPad

The app requires iOS/iPadOS 16.4 or later. Building it requires macOS with a current Xcode supporting the Capacitor 8 projects. Install the iOS simulator components in Xcode, then run the preparation commands above on your Mac.

npm run mobile:ios

Xcode opens mobile/ios/App/App.xcodeproj. Allow Swift Package Manager to resolve its packages, select the App scheme and an iPhone simulator, and click Run. CocoaPods is not required.

For your own iPhone, select your connected device, enable Developer Mode if requested, and choose your development team under App → Signing & Capabilities. If needed, choose a bundle identifier registered to your team and keep it stable for subsequent installs. Xcode handles device provisioning. TestFlight and App Store distribution require Apple Developer Program membership and an archive signed with your team’s credentials.

The iOS source project is supplied. iOS compilation, signing, and physical-device testing require a Mac and are not established by an Android build or browser tests. A simulator build is not an installable iPhone IPA.

4. Connect OCR and speech on a phone

Offline tracing needs no gateway. In an installed app, gateway fields start empty. Use a reachable HTTPS address such as https://your-private-gateway.example/api/ocr and https://your-private-gateway.example/api/speech. Enter the OCR address in the tracing connection settings; enter the speech address when adding a service voice.

localhost and 127.0.0.1 on your phone refer to your phone. They do not reach the Node server on your computer. The installed app rejects those gateway addresses. A computer’s plain HTTP LAN address is also rejected.

  1. Set up the Node companion and provider variables using the OCR & speech guide. Keep your working Gemini/OpenAI/model configuration on the server.
  2. Expose the loopback companion through a trusted HTTPS reverse proxy reachable by your device. A private VPN gateway is suitable. Keep access private or protect it with server-side access controls; the companion is not a complete public authentication service. Do not publish an unrestricted paid-provider gateway.
  3. Allow the installed origins on that server, then restart it. The comma-separated values are exact origins:
BHAASA_OCR_ALLOWED_ORIGIN=https://localhost,capacitor://localhost
BHAASA_TTS_ALLOWED_ORIGIN=https://localhost,capacitor://localhost

Android uses https://localhost; iOS uses capacitor://localhost. If you also use the browser app, append its exact origin, for example ,http://127.0.0.1:4173. CORS restricts browser access; it is not user authentication. Keep provider keys in the gateway’s environment or secret store, never in the app bundle or a gateway URL. No client secret or custom authorization-header field is provided in the app.

Use Check OCR connection or the speech connection check, then explicitly request a recognition/generation test. Model availability, quota, cost, and handwriting/pronunciation quality depend on the provider. A local OCR/TTS engine can sit behind the same private HTTPS gateway; the phone does not install or run that model.

Device voices: the installed app uses native text-to-speech and lists voices for the selected language reported by the operating system. Install Malayalam or French speech data in your device’s speech/accessibility settings if available. The app does not substitute a voice from another language. Some voices require internet. Device speech cannot be saved as generated audio; use a service or a microphone/file recording for reusable clips.

Recording: microphone permission is requested when recording begins. If denied, enable it in device settings, or import an audio file. Native microphone and audio behavior should be checked on your particular phone.

5. Save and move your work

Progress and audio are private to the installed app. They are separate from your browser/PWA data. To move existing work, export progress JSON and audio ZIP from the browser, transfer those files to the phone, then import them in Your progress and Voices & recordings.

Export progress, audio, or tracing strokes to open the native share sheet. Choose a file-saving destination (such as Files/Drive) or another sharing app to keep a copy outside Bhaasa. Cancelling sharing does not create an external backup. Temporary export copies use the app’s cache.

Clearing app storage, uninstalling, or installing an incompatible signing identity can lose local work. Export both progress and audio first. Android automatic app backup is disabled; keep explicit portable exports. Future releases should retain stable content IDs and the application ID.

6. Verification and distribution

npm test
npm run mobile:sync

The repository’s Build mobile apps GitHub Actions workflow can be run manually for Android, iOS simulator, or both. It uploads a debug APK and/or an unsigned simulator build. It does not publish to stores, create signing credentials, or produce a signed iPhone app.

Before distributing, test on real phones: finger/stylus tracing, resume after backgrounding, offline lessons, installed Malayalam voices, microphone permission and recording playback, imports/exports, and OCR/TTS through your reachable gateway. Browser tests exercise the shared UI and mock native adapters; they do not establish hardware behavior.

The iOS project includes microphone usage text and a privacy manifest for plugin file timestamps and preferences. Review actual provider data handling, store privacy disclosures, signing, and release requirements for your deployment. No store account or release signing key is included.

Brand assets come from mobile/assets/. To regenerate platform icons and splash screens after editing those sources, run npm run icons --prefix mobile, then sync again.
