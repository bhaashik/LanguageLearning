Bhaasa on Linux and Windows

The portable desktop app includes the lessons, fonts, tracing guides, and a local OCR/TTS gateway. It uses a browser already on your computer. You do not need hosting space, a separate Node.js installation, or a separately running gateway for this desktop package. Cloud generation/recognition still need internet and your own provider account.

1. Browser choices

An app cannot embed arbitrary default-browser engines interchangeably. A system WebView build would use Windows WebView2 or Linux WebKitGTK. Bhaasa’s desktop package instead opens an installed browser process, which avoids shipping another browser engine.

ChoiceHow it opensWhere progress/audio live
Automatic (initial setting)Prefer a supported system default; otherwise try Chrome, Edge, Chromium, Brave, then Firefox. Fall back to the system default if none is found.Depends on the selected browser below.
Chrome / Edge / Chromium / BraveA dedicated app window with less browser chrome.That browser’s normal profile, at Bhaasa’s local address.
FirefoxA normal Firefox window.Your normal Firefox profile, at Bhaasa’s local address.
System defaultA normal browser window or tab using your OS preference.Your normal browser profile, at Bhaasa’s local address.

Change the choice in About → Desktop settings. It applies on the next launch. Use a modern browser; Chromium-family browsers should be version 109 or later. Malayalam device voices and microphone/audio support depend on that browser and your OS. Saved/imported audio and connected speech services remain available if no Malayalam device voice is installed.

All choices use the browser’s normal profile, so Snap/Flatpak installations do not need access to a custom Bhaasa profile folder. Firefox has no Chrome-style app-window mode.

2. Install and run

The Build desktop apps workflow under the repository’s GitHub Actions can be run manually to produce a Linux archive and/or Windows ZIP. These are portable builds for the runner’s architecture (the supplied workflow uses x64). Extract the archive before running the app.

Linux

Use a current Linux desktop with a supported installed browser. The included official Node runtime requires compatible system libraries (glibc 2.28 or later on x64); this build does not target Alpine/musl. In the extracted folder:

./Bhaasa
# Optional: add an application-menu entry pointing to this executable
./Bhaasa --install

Keep the executable at the installed location. If you move it, run --install again. To remove the menu entry, delete ~/.local/share/applications/io.github.bhaashik.bhaasa.desktop (or the corresponding XDG_DATA_HOME path). Deleting the executable/menu entry does not delete the selected browser’s stored progress.

Windows

Use Windows 10 or later with a supported browser. Open Start Bhaasa.vbs in the extracted folder to launch without the server console. Alternatively open Bhaasa.exe directly; this works if Windows Script Host is disabled and shows startup messages. You can create a normal Windows shortcut to either file. This is a portable ZIP rather than an MSI installer.

While running

Bhaasa uses http://127.0.0.1:4174/. Settings are at http://127.0.0.1:4174/desktop/. It listens only on your own computer. A second launch reuses an existing compatible instance with the same data directory. Closing every Bhaasa/help/settings window stops the local server after about 30 seconds. The settings page also has an immediate quit button.

Core lessons and tracing work without internet as long as the local app is running. Its files are included in the executable; browser service-worker caching is disabled for desktop builds so new versions load their packaged lessons.

3. OCR and speech configuration

Open Desktop settings to see your private settings directory. It normally is:

Linux:   ~/.config/bhaasa/
Windows: %APPDATA%\Bhaasa\

Create providers.env there. You can copy the working provider lines from your existing .env.local. Use the exact same BHAASA_OCR_… and BHAASA_TTS_… variables described in the provider guide. For example, fill in your own values:

BHAASA_OCR_GEMINI_API_KEY=YOUR_GOOGLE_API_KEY
BHAASA_OCR_GEMINI_MODEL=YOUR_AVAILABLE_IMAGE_CAPABLE_MODEL_ID
BHAASA_TTS_PROVIDER=openai
BHAASA_TTS_API_KEY=YOUR_OPENAI_API_KEY

Quit and restart Bhaasa after changing this file. Existing process environment values take precedence. Only provider variables are read from this file; it is not a place for arbitrary Node options.

The initial OCR address is http://127.0.0.1:4174/api/ocr; the speech address is http://127.0.0.1:4174/api/speech. Select your OCR provider and use Check OCR connection, then explicitly request recognition. The package includes the OpenAI Realtime transport, so no additional speech:install command is needed for it.

Keys stay in the local server process. They are not placed in the executable, lesson files, profile exports, or browser settings. Keep providers.env private. The desktop server accepts its own loopback origin; it is not a phone or public gateway. For a mobile app, follow the private HTTPS gateway instructions separately.

If your network requires an HTTP/HTTPS proxy, preserve your usual proxy and CA settings. Launch with NODE_USE_ENV_PROXY=1 to enable Node’s environment-proxy support for REST requests. The OpenAI WebSocket transport uses the inherited proxy. Do not disable TLS verification.

4. Progress, recordings, and updates

Progress is in localStorage and audio in IndexedDB for the selected browser/profile and local origin. Every choice uses that browser’s normal profile. Bhaasa’s settings directory stores provider configuration, browser preference, and a startup log; it does not contain the browser’s progress or audio databases.

Export both progress JSON and audio ZIP before changing browser choice, port, browser profiles, or computers. Changing between automatic choices after an OS default change can also select a different profile. Imports work as in the web app. Returning to the same browser profile and port restores that profile’s existing work.

Your existing browser app at 127.0.0.1:4173 uses a different origin from the desktop default at 127.0.0.1:4174. Move existing learning using the two exports/imports. Microphone permissions and download locations are managed by the selected browser.

To update, quit Bhaasa and replace its extracted executable/package while keeping the settings directory, browser choice, and port stable. No automatic updater is included. Use exports to keep portable backups; copying the executable alone does not copy progress, keys, or recordings.

Advanced settings can be placed in desktop.json:

{"browser":"auto","port":4174}

For nonstandard browser installations, the browser value can be a full path to a supported browser executable, without extra arguments. Command-line options override settings:

Bhaasa --browser default
Bhaasa --browser firefox
Bhaasa --data-dir /your/private/settings/folder
Bhaasa --no-open
Bhaasa --help

--no-open keeps the local server running until stopped with Ctrl+C or the quit button. Use .\Bhaasa.exe in PowerShell or ./Bhaasa in a Linux shell. BHAASA_DESKTOP_BROWSER, BHAASA_DESKTOP_PORT, and BHAASA_DESKTOP_DATA_DIR are optional environment equivalents.

5. Build from source

Use Node.js 24 from its official distribution, including its LICENSE file, on Linux or Windows. Run from your repository checkout:

git pull
npm run desktop:install
npm run desktop:start
# To create a portable executable for the current OS/architecture:
npm run desktop:package

Output: desktop/out/Bhaasa-linux-x64/ or desktop/out/Bhaasa-win32-x64/ (arm64 when built with an arm64 runtime). The executable contains Node’s runtime, the public app assets, and the local provider adapters. Download size is larger than the lesson files but avoids bundling Chromium.

Packaging uses Node’s single-executable application support and postject. Build on each target OS rather than cross-compiling. BHAASA_DESKTOP_NODE can select a different official Node 24 executable; its architecture must match the build process. BHAASA_DESKTOP_NODE_LICENSE can specify its matching license file if the distribution uses a nonstandard layout. Output packages include Node and dependency license notices.

The manual GitHub Actions workflow builds each platform on its native runner and uploads archives. A Linux build does not verify Windows execution, and CI/headless tests do not verify voices, microphones, or window behavior on every desktop. Windows signing and installer/store distribution are separate release work.

The regular npm test and npm run build still work without desktop dependencies installed. Mobile, desktop, and public web builds share the lesson code and remain separate packages.

6. Troubleshooting

  • No window: run the executable from a terminal to see its local address. Try --browser default, or open that address manually. Startup information is in desktop.log inside the settings directory.
  • Browser will not launch: try System default or the browser’s full executable path. Avoid launching the browser as root.
  • Port unavailable: close the program using port 4174. Bhaasa does not silently choose another port, because that would change the progress store. --port NUMBER is an explicit override; export first if changing an existing setup.
  • Scores/recordings seem missing: return to your previous browser/profile and port, then export and import the data into the new choice.
  • OCR/TTS not configured: check the exact provider variable names in providers.env, restart the desktop server, and check its connection status. The provider name is different from its exact model ID.
  • No Malayalam device voice: install one supported by the selected browser/OS, or use saved recordings or a speech gateway. The app does not substitute an English voice.
  • Server exits: all app/help/settings pages were closed or disconnected. Relaunch Bhaasa. Use --no-open if you intentionally want the server to stay running without an open page.
