Set up OCR and speech models

Use this guide on your computer to connect Bhaasa to common recognition and speech services. It can be saved or printed from your browser and is cached with the app for offline reading. New cloud requests still need internet. Examples are settings to fill locally, not credentials supplied with the app.

1. Start the local app

  1. Install Node.js 24, open a terminal in your Bhaasa checkout, and run git pull.
  2. Create or edit .env.local in that folder. Keep your existing working settings. This file is ignored by Git. Use API keys, not OAuth client IDs, client secrets, or chat-account passwords.
  3. Set the provider variables in the examples below, replacing every YOUR_… value. Restart the server after editing this file.
node --env-file=.env.local scripts/serve.mjs

Open http://127.0.0.1:4173. Stop a running server with Ctrl+C before restarting it. Close and reopen existing app tabs after an update. If you already use http://localhost:4173, keep that hostname consistently: browser progress is separate for different origins.

Only OpenAI Realtime speech needs the optional transport packages:

npm run speech:install

Static GitHub Pages hosting provides lessons and tracing. OCR and speech generation need a reachable gateway; when your keys are on your computer, opening your local Bhaasa app is the simplest setup. A subscription to ChatGPT, Gemini, Claude, or another chat app does not establish API access. Free API tiers and quotas depend on the model, account, region, and provider.

3. OCR: recognize your handwriting

Open Writing system → a symbol, conjunct, or syllable. Choose Handwriting recognition, expand Teacher guides, OCR connection & exports, and use Check OCR connection. It reports local configuration, defaults, and enabled models without generating a reading. The gateway address for the default local setup is http://127.0.0.1:4173/api/ocr.

Recognize my handwriting sends a black-on-white image of your ink only. The printed target, guide, arrows, symbol ID, and expected answer are excluded. An uncertain reading is not counted as a wrong letter. Saved readings are reused for unchanged drawings and provider settings. Use Request a fresh reading only when you want another request.

Google Gemini

Create a Gemini API key in Google AI Studio. In Cloud Console, the relevant service is Generative Language API; Google Cloud Vision is a different API. Server-side keys should not use browser HTTP-referrer restrictions. Restrict API access appropriately for your project.

BHAASA_OCR_GEMINI_API_KEY=YOUR_GEMINI_API_KEY
BHAASA_OCR_GEMINI_MODEL=gemini-2.5-flash
BHAASA_OCR_GEMINI_MODELS=gemini-2.5-flash

Select Google Gemini. List models from Gemini asks Google for model IDs using the server key, without sending a drawing or making a generation request. Set the exact available image-capable model ID in the singular _MODEL variable and include it in _MODELS if that list is set. Listing a model does not verify its image/JSON support, generation permission, free-tier allowance, or handwriting quality.

The example gemini-2.5-flash supports image input and has a specific no-thinking configuration in Bhaasa. Use another exact ID if your account’s current availability differs. TTS, image-generation, embedding, and research model IDs are not interchangeable with OCR models.

OpenAI vision

BHAASA_OCR_OPENAI_API_KEY=YOUR_OPENAI_API_KEY
BHAASA_OCR_OPENAI_MODEL=gpt-4.1-mini
BHAASA_OCR_OPENAI_MODELS=gpt-4.1-mini

Select OpenAI. The model must accept image input through the Responses API and support strict JSON output. Legacy BHAASA_OCR_API_KEY and BHAASA_OCR_MODEL settings remain supported. OpenAI OCR can reuse BHAASA_TTS_API_KEY only while the speech provider is OpenAI or unset. A dedicated OCR key is clearer when speech uses a different provider.

Anthropic Claude

BHAASA_OCR_ANTHROPIC_API_KEY=YOUR_ANTHROPIC_API_KEY
BHAASA_OCR_ANTHROPIC_MODEL=YOUR_IMAGE_CAPABLE_CLAUDE_MODEL_ID
BHAASA_OCR_ANTHROPIC_MODELS=YOUR_IMAGE_CAPABLE_CLAUDE_MODEL_ID

Select Anthropic Claude. Copy a complete vision-capable API model ID available to your account; Claude alone, a web-chat name, or a wildcard is not an API model ID. The Messages API transcribes the ink and must return the requested JSON. Raw provider output is validated before scoring.

Local vision models: Ollama or vLLM

Install and run the engine separately. For example, with Ollama running, download a vision model from its library:

ollama pull qwen2.5vl:7b
ollama list
BHAASA_OCR_COMPATIBLE_URL=http://127.0.0.1:11434/v1/chat/completions
BHAASA_OCR_COMPATIBLE_MODEL=qwen2.5vl:7b
BHAASA_OCR_COMPATIBLE_MODELS=qwen2.5vl:7b

Select Local / OpenAI-compatible vision model. The URL must be the full chat-completions endpoint. For vLLM, use its actual port and loaded model ID. Set BHAASA_OCR_COMPATIBLE_API_KEY if that service requires authentication. The model must accept inline image data URLs and follow the JSON instruction. Bhaasa does not install model weights or guarantee that any particular local model reads Malayalam handwriting well. Hardware and disk requirements belong to the selected engine. Once its model is installed, a local service can work without cloud APIs.

Custom OCR: Tesseract, PaddleOCR, or another engine

Choose Custom OCR endpoint. An engine needs a small HTTP adapter implementing the contract below; its ordinary CLI or Python function is not directly an HTTP gateway. Configure the engine for Malayalam. Printed-text OCR models can perform poorly on handwriting and joined syllables.

POST /recognize
Content-Type: application/json

{"image":"data:image/png;base64,…"}

200 application/json
{"text":"ക്കോ","legible":true}

// An unreadable drawing:
{"text":null,"legible":false}

Do not pass the expected answer to the engine. Return only the recognized Unicode text, with optional provider/model labels. With a direct custom endpoint, the browser sends only image; the endpoint must allow the app’s exact origin via CORS. For server-held authentication, use:

BHAASA_OCR_PROVIDER=custom
BHAASA_OCR_CUSTOM_URL=http://127.0.0.1:9000/recognize
BHAASA_OCR_CUSTOM_API_KEY=YOUR_OPTIONAL_CUSTOM_SERVICE_KEY

Then use Custom OCR with the Bhaasa endpoint http://127.0.0.1:4173/api/ocr. The server forwards the image and optional Bearer key to your configured adapter. Omit the key line for unauthenticated local services. Named OCR providers still use their own explicitly selected adapters; BHAASA_OCR_PROVIDER controls image-only/default clients.

4. TTS: generate and save speech

OCR and speech are independent. A successful Gemini vision request does not configure a speech voice. The built-in speech gateway selects one speech provider per server process; multiple OCR providers can coexist. Set the speech provider, key, enabled speech models, and default voice, restart, and open Voices & recordings → Add a voice or speech model.

  1. Source: Speech service / model.
  2. Give the profile a name. Enter the exact provider, model, and voice IDs shown below.
  3. Set Speech gateway URL to http://127.0.0.1:4173/api/speech.
  4. Discover service models reports the server-enabled models and configured voice; it does not generate audio.
  5. Add the profile, choose a single item, and use Generate & save clip. Audition Malayalam before generating a larger collection.

Leave Save a speech model’s audio the first time it is generated checked to reuse clips. A new provider/model/voice identity keeps a separate collection. Generate & replace clip explicitly overwrites the current identity. Export your audio ZIP before replacing recordings you want to keep. Gender is a user/provider label, not inferred from the voice name.

Google Gemini speech

BHAASA_TTS_PROVIDER=gemini
BHAASA_TTS_API_KEY=YOUR_GEMINI_API_KEY
BHAASA_TTS_MODELS=gemini-2.5-flash-preview-tts
BHAASA_TTS_VOICE=Kore

Profile provider: gemini; model: gemini-2.5-flash-preview-tts; voice: Kore. Use another Gemini speech-generation model or prebuilt voice only if it is available to your project. The regular vision model gemini-2.5-flash is not a substitute for the speech model. Copying the same Google API key into the local OCR and TTS key variables is fine if the project grants both capabilities; no key goes into the browser.

Bhaasa requests single-speaker audio and wraps the returned 24 kHz, mono, 16-bit PCM in a playable WAV file. No optional OpenAI transport installation is needed for Gemini. Incomplete/filtered audio is rejected instead of being cached. Quota, preview-model availability, language support, and pricing are controlled by Google.

OpenAI speech

BHAASA_TTS_PROVIDER=openai
BHAASA_TTS_API_KEY=YOUR_OPENAI_API_KEY
BHAASA_TTS_MODELS=gpt-realtime-2.1-mini
BHAASA_TTS_VOICE=marin

Run npm run speech:install once. Use the app’s OpenAI setup panel to choose a configured model/voice and add its profile. Realtime speech saves WAV audio. The legacy gpt-4o-mini-tts, tts-1, and tts-1-hd adapters save MP3; consult the provider’s current lifecycle information and the app’s labels before choosing older models. ChatGPT voice subscriptions do not automatically supply API billing.

ElevenLabs

BHAASA_TTS_PROVIDER=elevenlabs
BHAASA_TTS_API_KEY=YOUR_ELEVENLABS_API_KEY
BHAASA_TTS_MODELS=YOUR_MALAYALAM_CAPABLE_MODEL_ID
BHAASA_TTS_VOICE=YOUR_ELEVENLABS_VOICE_ID

Profile provider: elevenlabs; model and voice: the exact IDs from your ElevenLabs account. A voice ID is not its display name. Confirm that the chosen model currently supports Malayalam; do not assume every “multilingual” model does. The gateway’s legacy default eleven_multilingual_v2 is not a recommendation for Malayalam—set an explicitly suitable model. Synthetic voices and pronunciation still need review.

Device speech and recordings

For device speech, select an installed Malayalam voice in the app. Install Malayalam speech data in your OS/browser settings if none is reported. No cloud API key is needed, but some device voices use network services. Web Speech does not expose audio bytes, so Bhaasa cannot save device speech as a recording.

For audio made in another tool—Gemini Studio, Azure Speech Studio, Google Cloud TTS, Piper, Kokoro, or a human recording—create a Recording / imported audio profile with the real provider/model/voice labels, select the exact item, and use Import / replace audio. Use a voice that actually supports Malayalam. These external tools’ voices are not bundled. Imported clips preserve your chosen identity; they do not require a live gateway. Microphone recordings use Stop & save.

5. Other speech services and local engines

Azure Speech, Google Cloud Text-to-Speech, Piper, Kokoro, Coqui, and other services can be connected through a compatible speech HTTP adapter. They are distinct from the native Gemini/OpenAI/ElevenLabs adapters. Use a language-capable voice/model available from that engine; availability of a French or English voice does not establish Malayalam support.

BHAASA_TTS_PROVIDER=custom
BHAASA_TTS_URL=http://127.0.0.1:9001/tts
BHAASA_TTS_MODELS=YOUR_ADAPTER_MODEL_ID
BHAASA_TTS_VOICE=YOUR_ADAPTER_VOICE_ID

Set BHAASA_TTS_API_KEY only if this adapter needs a Bearer token. In Bhaasa, create a service profile with provider custom, the same enabled model/voice IDs, and the local Bhaasa /api/speech gateway. The adapter receives:

POST /tts
Content-Type: application/json
Authorization: Bearer OPTIONAL_ADAPTER_KEY

{"input":"നന്ദി","language":"ml-IN","provider":"custom",
 "model":"YOUR_ADAPTER_MODEL_ID","voice":"YOUR_ADAPTER_VOICE_ID",
 "response_format":"mp3"}

200 Content-Type: audio/wav
[binary WAV bytes]

The adapter maps input/model/voice to its engine’s own API and returns binary audio, never JSON-wrapped/base64 audio. It may return audio/wav even though the forwarding request offers MP3. For Google Cloud TTS this means decoding its audioContent; for Azure it means making its authenticated SSML/audio request; for a local CLI it means running the selected voice and returning its generated file. Keep those engines’ credentials in the adapter, not in the app. Direct custom gateways can also implement GET /models:

{"configured":true,"models":[{"id":"YOUR_ADAPTER_MODEL_ID",
 "provider":"custom","voices":[{"id":"YOUR_ADAPTER_VOICE_ID",
 "name":"My Malayalam voice","gender":"unspecified"}]}]}

A direct service gateway must match the provider field in your saved profile and allow the app’s exact origin. URLs must use HTTPS or HTTP loopback, with no embedded key, query string, or fragment. Connecting a CLI requires building/running this adapter; changing a URL alone does not convert its protocol. Importing generated audio files is available if you do not want to run an adapter.

Keep multiple speech providers available

Run separate Bhaasa server processes on different ports, each with a separate ignored environment file and provider. For a second service, set:

PORT=4174
BHAASA_TTS_ALLOWED_ORIGIN=http://127.0.0.1:4173
# Add that service's BHAASA_TTS_PROVIDER, API_KEY, MODELS, and VOICE.

node --env-file=.env.second-service.local scripts/serve.mjs

Keep the learning app open on port 4173 and add a voice profile pointing to http://127.0.0.1:4174/api/speech. Use a different port per service, and the exact origin actually used by your browser. OCR keys remain provider-specific; another service never borrows the OpenAI key.

6. Troubleshooting

SymptomAction
Check my tracing is greyed outDraw a full-size form and release the pen/finger/mouse. Watch the status below the buttons. Retry loading the practice guide if needed. The demo is not your ink. No gateway or key is needed for tracing.
Google did not list an HTTP URLA gateway address is in Model ID. Put the URL in the gateway field and an exact model name in Model ID, or leave Model ID blank for the default.
Model is not enabled / HTTP 400Use Check OCR connection to see server-enabled IDs. Match the exact model, add it to the matching server _MODELS list, and restart. Do not paste a URL or provider name as the model.
Invalid key, restricted key, API disabledReview the key’s project, API access, and application restrictions. OAuth web-client credentials are not API keys. Never paste your key into chat or a screenshot.
HTTP 403 on localhostKeep localhost or 127.0.0.1 consistent. For a separate gateway, allow the app’s exact origin on that server.
HTTP 429Review the model’s project quota/rate limit and free-tier availability. Wait for the quota window or explicitly choose another available service; Bhaasa does not silently switch paid models.
Provider HTTP 503/502The provider reported a temporary failure. Wait and retry explicitly. Another enabled model can be tried without changing the key or gateway.
Local HTTP 502, MAX_TOKENS, invalid JSON, or no textUpdate Bhaasa, restart the Node server, reopen the tab, and read the specific response error. Gemini 2.5 Flash/Flash Lite use a no-thinking request and a 4096-token cap. Partial/filtered/invalid replies are not scored, and failed requests are not retried automatically.
Speech returns HTTP 400The profile provider, model, and voice must match the selected speech server. TTS requires a speech model, not a vision model. Check case-sensitive voice IDs.
Gemini speech fails or produces no playable fileUse a speech-generation model and prebuilt voice available to your project. Bhaasa accepts completed single-speaker 24 kHz PCM audio and saves WAV. Check speech quota separately from OCR.
OpenAI Realtime cannot connectInstall the optional transport with npm run speech:install. Check API access, network/proxy, and normal TLS trust; do not disable certificate verification.
A new model/voice plays an older recordingCheck the selected profile identity and exact content text. Use Generate & replace clip or Import / replace audio deliberately. Different model/voice identities keep separate clips.

For a safe configuration report, open http://127.0.0.1:4173/api/ocr or http://127.0.0.1:4173/api/speech/models. These list configured model names and status, not API keys. “Configured” means local settings exist; it does not prove live API permission or quality.

7. Conjunct and syllable practice

Open Writing system → Conjuncts for the expanded cluster reference. Writing system → Syllables combines any of the 36 consonants or 32 conjuncts with 14 patterns: the inherent vowel, vowel signs including learned vocalic ṛ, and the no-vowel chandrakala form. Choose any preview or card to open its tracing/OCR pad.

All 952 combinations have full-form guides. Existing shapes reuse their original cards; added forms keep independent drafts, tracing checks, OCR readings, recordings, and backups. Stroke demos, guide hiding, pen-lift/smoothness feedback, teacher-guide import, and touch input work the same way. Section-level script audio keeps the reference sequence; extra syllables can be recorded/generated individually.

Some generated combinations are uncommon or not words. Example words are shown when supplied by the course; other forms are explicitly constructed practice. Roman, broad IPA, extended Devanagari, and sound-unit glosses are teaching aids. Font-derived paths suggest a practice route and are not teacher-verified Malayalam handwriting stroke order. Detached marks can require three or more strokes; some complex forms have up to five suggested strokes; another valid handwriting style may use a different route.
